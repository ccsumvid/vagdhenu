A Second Voice for Vāgdhenu

Voice packs: one fine-tuned checkpoint and one per-meter reference bank per reciter, selectable at render time — the chant behavior carries over unchanged.

Design plan · 2026-07-30 approved

pilot — the shipped voice reciter-2 — the new voice shared infrastructure

Decision

Three routes were weighed; voice packs won on safety and extensibility.

chosen

Voice packs

Per-voice checkpoint + per-voice reference bank. Zero risk to the shipped MOS-4.6 voice; voices fully independent; extends naturally to more reciters.

later, maybe

One multi-reciter model

Single checkpoint on both corpora; reference clip selects the voice. Moves toward voice-agnostic chant, but risks regressing the shipped voice. A research track once packs are stable.

rejected

Zero-shot reference swap

No training — a new-voice bank on existing weights. Single-speaker weights pull timbre toward the pilot reciter; not the right use of hours of studio data.

Inputs for the new voice: hours of studio recordings — metrical ślokas across multiple meter families, transcribed per verse, plus prose (gadya).

Voice pack layout

A voice is a directory: manifest, bank, clips. The checkpoint lives on Hugging Face, as today.

VAGDHENU_VOICE env and a --voice CLI flag select a pack. Default is pilot — existing invocations change nothing.

Training pipeline

Four phases, in order — every script already exists in training/; only the data is new.

Data preparation

phonemize_corpus.py → tts_build_training.py over the transcribed corpus — metrical and prose. The same prep_text frontend applies: Kannada routing and sandhi rules are identical for every voice.

Prose chunks on safe word boundaries with a gadya label instead of a meter key — it adds phonetic coverage in a non-metrical register.

Voice fine-tune

finetune_indicf5.py, warm-started from the GRN-corrected Indic checkpoint — not from the pilot voice, to avoid inheriting its timbre. lr 1e-5 · bf16 · 100-band mel @ 24 kHz. Runs on the A6000 host.

Voice-steering retrain

phase2_finetune.py with ~150–200 paired clips from the new corpus, mirroring the shipped 179-clip recipe, so the new voice responds to reference clips — the system's only working prosody lever.

Reference bank build

Per meter: a half-hemistich clip (~7 s, clean daṇḍa boundary) with exactly-matching text; sec_per_syll measured from the new reciter's actual pace; repeat-primes selected or recorded. Gadya entries included, with prose pace calibrated separately from chant pace.

The half-reference rule holds: reference text must match the spoken span exactly, on a clean word or daṇḍa boundary. BigVGAN stays shared — a per-voice vocoder fine-tune only if by-ear checks reveal artifacts.

Small and surgical — one new module, one flag threaded through.

Verification

By-ear, per the project's QC philosophy — with one hard regression gate.

  • Regression gate. Render examples/sample_shard.json with --voice pilot before and after the refactor — durations must match the prior good output exactly.
  • New-voice hard cases. Same shard with --voice reciter2; by-ear check retroflex conjuncts (ṣṭ, ḍḍh), long-vowel daṇḍa-final visarga, a repeat-prime verse, one held-out meter, and a prose chunk.
  • Automatic gates unchanged. The duration gate and internal-silence gate run as-is — they are voice-agnostic.

Constraints & scope

Locked parameters stay locked NFE, sway coefficient, speed, and CFG are voice-independent and unchanged. No edits to the frontend, meter detection logic, or inference defaults.
Known limits persist Repeated-syllable depth beyond ~4 remains unrecoverable in any voice — a documented limitation, not a bug to fix in this project.
Consent before training The new reciter's explicit consent is obtained and recorded before any fine-tune, referenced from voice.json. The system stays liturgical-register — not a general voice-cloning tool.
Out of scope The multi-reciter single model (a later research track) and voice-agnostic zero-shot chant.
